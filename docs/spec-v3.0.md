# IT-Tycoon v3.0 設計規格書

## 核心定位

「從 Y2K 時代的第一台 Dell 伺服器，到 AI 基礎設施競賽的 H100 叢集——你要在二十五年的科技巨變中，同時應付採購簽呈、資安事件、SLA 違約賠償，還有每一個讓 IT 預算蒸發的黑天鵝。」

**遊戲類型：管理模擬 / 經營 Tycoon（類 Game Dev Tycoon / Startup Company）**

核心張力：**歷史科技演進感 ↔ 現實官僚摩擦 ↔ 外部宏觀不確定性 ↔ P&L 壓力 ↔ 現金流管理**

> v3.0 重大變更：遊戲類型從 idle/incremental 改為純管理模擬。移除自動累積（CPS）、離線收益、點擊產生資源、Prestige 重生等 idle 機制。玩家主動推進時間、做決策，而非等待被動累積。

---

## 遊戲類型定義

### 不是什麼
- ❌ 不是 idle 遊戲（沒有「放著讓它跑」的機制）
- ❌ 不是點擊遊戲（沒有點擊產生資源）
- ❌ 不是 Prestige 重生遊戲（不重置時間軸）
- ❌ 沒有抽象貨幣（算力幣、聲望點、影響力）

### 是什麼
- ✅ **主動決策**：玩家控制時間流速，遇重大事件自動暫停等待決策
- ✅ **真實財務**：以 NTD 為主要資源，有資產負債表、損益表、現金流量表
- ✅ **成長弧線**：從小機房成長為區域雲端服務商，有明確里程碑
- ✅ **歷史沉浸**：二十五年科技演進，真實硬體型號與歷史事件
- ✅ **策略深度**：資源分配、風險管理、時機判斷缺一不可

### 自動暫停觸發條件

遇到以下情況，遊戲自動降速至暫停並跳出決策面板：

| 觸發條件 | 說明 |
|---------|------|
| P1/P2 事件發生 | 緊急資安/硬體事件需立即決策 |
| 合約到期提醒（1 個月前）| 需決定是否續約/修改條款 |
| RFP 收到 | 客戶請求報價，需決定是否投標 |
| 重大歷史事件觸發 | Y2K、金融海嘯、COVID 等強制暫停通知 |
| 資金低於警戒線 | 現金低於月支出 × 2 時警告 |
| 設備 EOL/EOS 到期 | 提前 1 個月通知需要處理 |
| 月結算完成 | 顯示本月 P&L 摘要（可設定跳過）|

> **設計原則**：自動暫停是遊戲提示玩家「現在有重要事情需要你決定」，而非懲罰機制。玩家可在設定中調整哪些事件觸發自動暫停。

### 1.3 支出項目詳細

#### 硬體折舊

```
月攤提 = 硬體採購價 / 折舊年限（月數）

折舊年限：
  伺服器類       5 年（60 個月）
  網路設備       7 年（84 個月）
  儲存設備       5 年（60 個月）
  UPS / 電源    10 年（120 個月）
  設施建設      20 年（240 個月）

殘值 = 10%（折舊到期後停止攤提但仍計 EOL 風險）

注意：折舊為非現金支出，影響損益表但不影響現金流。
     現金流衝擊在採購時一次發生（或分期付款時按期發生）。
```

#### 電力成本

```
月電費 = Σ(設備功耗 W) × 744 小時 × 電費單價(NT$/kWh) × PUE / 1000

電費單價：
  2000–2010 年：NT$2.5/kWh
  2011–2020 年：NT$3.0/kWh（311 後能源轉型）
  2021–2021 年：NT$3.2/kWh
  2022–2025 年：NT$4.0/kWh（俄烏戰爭能源成本）
  
econElecMod 乘數由國際事件動態調整（範圍 0.8–2.5）
```

#### 頻寬成本

```
月頻寬費 = 實際使用頻寬(Mbps) × 單價(NT$/Mbps/月)

頻寬單價（隨時代下降）：
  2000–2004 年：NT$2,000/Mbps
  2005–2009 年：NT$500/Mbps
  2010–2014 年：NT$100/Mbps
  2015–2019 年：NT$20/Mbps
  2020+ 年：NT$5/Mbps

頻寬需求 = Σ 各合約服務的頻寬分配
```

#### 人力成本

```
月人力成本 = Σ 各員工月薪 × 1.3（法定福利、勞健保、退休金提撥）

月薪基準（台灣市場，隨時代通膨調整）：
  NOC 技術員：NT$35,000–45,000（2000 年基準）
  系統工程師：NT$50,000–70,000
  資安分析師：NT$60,000–80,000
  雲端架構師：NT$80,000–120,000（2010 年後職位）
  AI 工程師：NT$100,000–200,000（2018 年後職位）

每年薪資通膨 2–3%（依通膨率調整）
```

#### 維護合約費

```
月維護費 = Σ(設備原始採購價 × 維護費率 / 12)

維護費率：
  原廠保固內（3 年）：費用含購買價，月費為 0
  延保 (Next Business Day)：採購價 × 8%/年
  延保 (4-Hour Response)：採購價 × 12%/年
  EOL 設備（停產後）：採購價 × 20%/年（第三方維護）
  EOS 設備（軟體停止支援）：另加資安合規保險費
```

#### 利率隨時代變化


### 2.3 信用評等影響因素

| 因素 | 正面影響 | 負面影響 |
|------|---------|---------|
| 連續盈利月數 | 每月 +0.5 分 | 虧損月 −2 分 |
| 負債比率（貸款/資產）| < 30% +1 分 | > 70% −3 分 |
| 現金覆蓋率（現金/月支出）| > 6× +1 分 | < 2× −2 分 |
| SLA 違約次數 | 0 次 +0.5 分 | 每次 −1 分 |
| 重大資安事件 | — | 每次 −2 分 |
| 持有 ISO 27001 認證 | +1 分 | — |
| 準時還款記錄 | 每年 +1 分 | 逾期 −5 分 |

信用評等每季更新一次。

### 2.4 失敗條件

以下任一條件成立即觸發**遊戲結束**：

1. **現金流破產**：連續 3 個月現金流為負，且信用評等 < B（無法借貸）
2. **重大資安事件清零**：單一資料外洩/APT 事件導致所有客戶合約在 3 個月內流失
3. **電費斷電**：現金歸零且無法貸款時，電費無法支付，所有服務停機，客戶合約自動終止

> **設計原則**：遊戲結束是戰略失敗的結果（做錯了一系列決策），而非突發意外。遊戲應在失敗前 3–6 個月提供足夠警示（財報惡化、信用降等通知、現金流警告）。

### 2.5 勝利條件（里程碑系統）

採取**里程碑式勝利**設計，玩家達成里程碑後解鎖下一階段目標：

| 里程碑 | 解鎖時機 | 達成條件 |
|--------|---------|---------|
| 第一桶金 | 開局 | 累計營收突破 NT$1,000 萬 |
| 穩健基礎 | 2002+ | 連續 12 個月正向現金流 |
| 區域玩家 | 2005+ | 同時持有 10+ 份有效合約 |
| 技術領先 | 2008+ | 科技樹解鎖 20 節點 |
| 跨區巨頭 | 2010+ | 三區機房同時運營 |
| 上市準備 | 2015+ | 年度營收 > NT$5 億 + 持有 ISO 27001 |
| 雲端轉型 | 2018+ | AI/ML 服務佔收入比 > 30% |
| 區域雲端服務商 | 2023+ | 年度營收 > NT$20 億 + AI GPU 叢集 |

#### 採購成本修正

```
實際採購價 = 基礎採購價 × econHardwareMod × exchangeRateMod

econHardwareMod：受景氣循環、晶片短缺等事件影響（0.7–2.5）
exchangeRateMod：匯率波動影響進口設備（0.9–1.3）

ODM 品牌（Supermicro）：基礎採購價 × 0.75（管理工具加成 −10%）
品牌溢價（IBM, Cisco UCS）：基礎採購價 × 1.25（管理工具加成 +10%）
```

### 11.3 合約生命週期

```
RFP 收到 → 評估能力（可行性分析）→ 決定投標價格/條款
→ 談判結果（勝標/落標）→ 簽約 → 履約期
→ 合約到期前 1 月自動暫停通知 → 續約談判 → 續約/流失
```

**合約談判參數（玩家可調整）：**

| 參數 | 影響 | 風險 |
|------|------|------|
| 月費金額 | 越高越好，但超過市場行情易落標 | 定價過高 → 失去合約機會 |
| SLA 等級 | 越嚴苛月費越高，但違約賠償也越重 | 定過嚴 → SLA 違約風險大 |
| 合約期限 | 長約穩定但綁死 | 3 年約若服務品質下降無法解約 |
| 違約金條款 | 對客戶提前終止的保護 | 玩家違約賠償上限需設定合理 |
| 特殊服務附加 | 加值服務提高月費 | 增加履行複雜度 |

### 11.4 SLA 違約賠償

```
SLA 違約賠償 = 受影響合約月費 × 賠償比例（10%–500%）

賠償比例由 SLA 等級和事件嚴重度決定：
  99.5% SLA + P2 事件超時：月費 × 10%
  99.9% SLA + P1 事件超時：月費 × 50%
  99.95% SLA + P1 事件：月費 × 100%
  99.99% SLA + P1 事件：月費 × 200%
  99.99% SLA + 資料外洩：月費 × 500%

注意：賠償在月結算時一次扣款，不是即時扣款。
     月度總賠償上限 = 當月總合約收入 × 300%（破產保護上限）。
```

### 11.5 合約流失機制

客戶在以下情況可能提前終止合約（需支付提前終止費給玩家，或由玩家支付違約金）：

| 原因 | 客戶終止機率 | 連帶效應 |
|------|------------|---------|
| 資料外洩且通報超時 | 70% | 同類型客戶滿意度 −10 |
| 連續 3 個月 SLA 違約 | 50% | 口碑受損，新客戶詢問減少 |
| P1 事件超過 24 小時未解決 | 40% | 其他合約警戒 +20% 流失機率 |
| 滿意度 < 40 超過 2 個月 | 30% | — |
| 提供更優惠競品方案（AI 事件）| 20% | 若無差異化服務 |

### 13.2 人力效率係數

```
coverageRatio = 員工總管理能力(U) / 已部署硬體 U 數

coverageRatio ≥ 1.0：滿載，服務品質正常，可考慮裁員節省成本
coverageRatio 0.7–1.0：工作量偏高，SLA 達成率受輕微影響
coverageRatio 0.5–0.7：人力不足，故障處理慢，SLA 風險上升
coverageRatio < 0.5：嚴重人力不足，P1 事件處理能力大幅下降
```

### 13.3 人力不足 Debuff

| coverageRatio | 故障率加成 | 事件處理速度 | 滿意度影響 | SLA 違約風險 |
|---------------|----------|------------|-----------|------------|
| 0.9–1.0 | ×1.1 | −10% | 無 | +5% |
| 0.7–0.9 | ×1.3 | −30% | −2/月 | +15% |
| 0.5–0.7 | ×1.8 | −50% | −5/月 | +30% |
| < 0.5 | ×2.5 | −70% | −10/月 | +60% |

### 13.4 排班機制

| 雙班制 | 08:00–24:00 | 接近 24hr | +40% 人力 |
| 三班制 | 全天候 24hr | 完整 | +80% 人力 |
| AIOps 自動（需科技樹）| 全天候 | 完整 + 人力成本 −30% | — |

## Section 14：異常與資安事件系統

### 14.1 事件嚴重度分級

| 等級 | 名稱 | 處理時限 | 未處理後果 | SLA 違約觸發 |
|------|------|---------|-----------|-----------|
| P1 | 緊急 | 4 小時（遊戲時間）| 服務完全中斷，每小時損失月收入 5% | 是（所有 SLA ≥ 99.9% 合約）|
| P2 | 嚴重 | 8 小時（遊戲時間）| 服務降級，每小時損失月收入 2% | 是（SLA ≥ 99.95% 合約）|
| P3 | 一般 | 24 小時（遊戲時間）| 效能下降，每小時損失月收入 0.5% | 否 |
| P4 | 輕微 | 48 小時（遊戲時間）| 輕微影響，每小時損失月收入 0.1% | 否 |

> P1/P2 事件觸發時遊戲**自動暫停**，玩家需做決策。

### 14.2 事件處理公式

```
處理時間 = 基礎處理時間 / (1 + Σ(工程師處理力))
工程師處理力：E1=0.5, E2=1.0, E3=2.0（資安類 ×2）, E4=4.0, E5=8.0
SOC 監控中心：處理時間 ×0.7
ITSM 平台：處理時間 ×0.85
```

### 14.3 異常事件

每月觸發頻率由設備老化程度和 EOL 設備數量決定：

| 事件 | 嚴重度 | 基礎處理時間 | 效果 | 觸發條件 |
|------|--------|------------|------|---------|
| 硬體故障（保固內）| P3 | 4 小時 | 設備停機，原廠快速更換 | 基本故障率 |
| 硬體故障（EOL 設備）| P2 | 8 小時 | 設備停機，零件難取得 | 故障率 ×2–3 |
| 硬體故障（EOS 設備）| P2–P1 | 12 小時 | 設備停機 + 資安風險並發 | 故障率 ×3 |
| 網路中斷 | P2 | 6 小時 | 某區域所有服務降級 | 每月 3% 基本機率 |
| 容量告警 | P4–P3 | 2 小時 | 若不處理：區域收入 −20%/天 | 使用率 > 85% |
| 電力異常 | P2–P1 | 8 小時 | UPS 切換，超時則停電 | 每月 2% 基本機率 |
| 冷卻失效 | P2 | 6 小時 | PUE 暫時 +0.5，故障率 ×3 | 每月 2% 基本機率 |

**EOL 硬體故障修復選擇：**

| 選項 | 成本 | 時間 | 結果 |
|------|------|------|------|
| 現場修復（原廠保固內）| 含於維護合約 | 4 小時 | 修好，故障率不變 |
| 現場修復（EOL 第三方）| 採購價 × 0.2 | 12 小時 | 修好，故障率仍高 |
| 換同代新機 | 採購價 × 1.0 | 即時 | 全新，故障率歸零 |

### 關鍵連動鏈說明

**1. EOL 連鎖崩潰路徑**
```
EOL 硬體不汰換 → 故障率 ×2–3 → P2/P1 事件頻發
→ 工程師被佔用 → SLA 違約觸發 → 合約賠償（P&L 惡化）
→ 客戶滿意度下降 → 合約流失 → 月收入下降
→ 現金不足汰換硬體（惡性循環）
```

**2. EOS 資安連鎖**
```
EOS 軟體不升級 → 合規分數下降 → 資安事件頻率暴增
→ 勒索軟體/資料外洩 → SLA 違約 + 合約賠償
→ 滿意度 −15 to −30 → 大量合約流失
→ 信用評等下降 → 貸款利率上升 → 財務壓力加大
```

**3. 歷史事件 × 準備度**
```
歷史事件提前 UI 顯示倒計時 → 玩家有時間備貨/升級/買保險
→ 有備而來 = 事件變機遇（抓住需求暴增）
→ 沒有準備 = 事件成危機（成本暴增、服務中斷）
```

**4. AI 時代轉型壓力**
```
2023 年後無 GPU 節點 → AI 合約競標資格喪失
→ 雲端競爭 × 無差異化 → VPS 合約持續流失
→ 月收入下滑 → P&L 惡化 → 無法投資 GPU（轉型困難）
（建議 2021 年開始籌備 GPU 基礎設施）
```

**5. 現金流 × 歷史周期**
```
金融海嘯（2008）→ 客戶削減 IT 預算 → 月收入 −25–40%
→ 若固定成本過高（人力+租金+授權+貸款利息）→ 月虧損
→ 現金快速消耗 → 信用評等下降 → 貸款利率上升
→ 財務惡化加速（複利負反饋）
```

## Section 19：待決事項

### 遊戲設計
1. **RFP 頻率曲線**：早期合約 RFP 應多頻繁出現？玩家應感受到「機會夠多，但要選擇性接受」
2. **合約談判深度**：是否加入多輪談判（客戶反還價），或維持單次決策？
3. **破產流程設計**：現金耗盡前給多少回應視窗？是否有緊急借貸機制？
4. **時代轉換視覺**：每進入新時代（2005/2010/2015/2020）是否有特殊演出或通知？
5. **存檔機制**：月結算後自動存檔，還是隨時可存？

### 數值平衡
6. **起始 500 萬的生存壓力**：2000 年的月收入 vs. 支出能否在 6–12 個月內達到損益平衡？
7. **銀行貸款利率曲線**：2008–2009 降息期間貸款成本應更有吸引力（鼓勵逆景氣擴張）
8. **AI 設備成本回收**：NVIDIA DGX H100 NT$900 萬，AI 合約月費 NT$10–50 萬，回收期過長？
9. **科技樹投資 ROI**：各節點的投資成本 vs. 長期收益是否合理？

### 系統整合
10. **歷史事件「強制觸發」vs「機率觸發」邊界**：WannaCry（強制）vs. 晶片短缺程度（機率）
11. **Broadcom/VMware 事件**：是否應強制觸發「評估遷移」決策介面，還是只調整成本？
12. **合規分數系統**：如何可視化讓玩家隨時了解合規狀態（不是數字，而是「狀態燈」）
13. **EOL/EOS 過渡期 UX**：設備從黃色警告到紅色警告的視覺轉換需要漸進設計
